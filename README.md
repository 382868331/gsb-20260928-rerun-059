# Python 协议健壮性研究系统

这是一个仅研究项目自带目标的确定性健壮性实验系统。研究目标、输入生成器和实验结果分离，运行预算与失败样本管理可复用于后续协议。

## 结构

- `goals/simple_message.json`：研究目标、目标解析器和失败分类策略。
- `targets/simple_message.py`：项目自带的二进制消息解析器及三个受控本地缺陷。
- `proto_robust/generator.py`：固定种子的语法输入与结构化变异生成器，内置定向样本。
- `proto_robust/runner.py`：每个候选从全新会话重放，独立进程执行、超时终止、异常退出回收，并在失败后更换工作进程。
- `proto_robust/stability.py`：按异常类型 + 缺陷位置 + 关键条件判定同一种失败，并保存重复试验证据。
- `proto_robust/reducer.py`：保持同一种失败的字节与前置交互缩减，逐步记录接受理由。
- `proto_robust/fuzzer.py`：预算控制、去重分组、失败样本、活动检查点和摘要落盘。
- `results/`：实验输出，默认运行不与目标和生成逻辑混放。

## 失败语义与分组

解析器主动抛出 `ParseReject` 归为 `rejected`，只代表拒绝畸形输入，不算健壮性缺陷。未预期异常归为 `crash`，超时归为 `timeout`，子进程异常退出归为 `runner_error`。每次确认或缩减尝试都会记录该分类；崩溃、超时和异常退出后，旧工作进程会被销毁，下一序列从新进程和新会话开始。

多个同类异常会被同时追踪：崩溃签名不仅包含异常类型，还包含缺陷所在文件、函数和行号，因此两个都抛出 `IndexError` 但位于不同代码位置的人工缺陷会分成独立发现。

## 内置缺陷

1. `operation-table`（索引 8，`534d01000001ff`）：payload 首字节 `ff` 把操作表下标算成 254，`IndexError`。
2. `channel-table`（索引 9，`534d0100000201fe`）：首字节是合法操作、第二字节 `fe` 越界访问通道表，`IndexError`，与第一个缺陷位置不同。
3. `timing-stall`（索引 10，`534d01000000` + flags `77`）：解析器在该 flags 下睡眠超过紧超时，表现为时序相关超时。
4. `guarded-channel-state`（索引 11）：必须先发送 flags=`40` 的 arming 消息，再发送 payload `02 00` 才会进入有状态越界；中间良性消息可删除，但 arming 前置交互不能删除。

## 缩减语义

缩减不只是保持异常类型，也不只缩减字节。每个候选序列都从完整会话起点重新执行，并同时确认：

- 完整交互顺序仍从新会话开始；
- 异常类型仍相同；
- 异常仍在原始缺陷位置（文件、函数、行号）抛出；
- 触发缺陷的关键步骤和字节条件（如最终交互 offset 7=`fe`、多会话缺陷的 arming 交互）仍满足。

缩减会先尝试删除整条前置/中间交互，再缩短单个交互。这样可以删除无关交互但保留跨会话状态，也避免把一个复杂缺陷缩成另一个只抛出相同异常的简单问题。每一步接受的缩减都会在样本 JSON 的 `reduction_steps` 中留下动作、完整序列、交互数、字节数、每轮尝试命中和文字理由；原始序列与当前最小候选分别独立保存，可直接重放。

## 偶发失败

新失败先重复试验（崩溃默认 5 次，超时默认 2 次），所有单次结果都写入 `confirmation.trials`，包括尝试序号、完整会话起点、交互顺序、交互数、字节数和分类，并记录命中数、试验数和复现率。一次重复没出现不会删除样本：复现率低于 1/3 时仍保留原始样本与证据，只是标记 `stable=false` 且不做缩减。缩减阶段的每个候选也要多次复现（多数命中才接受）。

## 预算、检查点与恢复

执行数量达到预算即标记 `budget_exhausted=true` 并停止。每个用例执行后都原子写入 `campaign.checkpoint.json`，记录下一个待执行索引、累计执行数、已发现签名和缩减是否完成。稳定故障在缩减前先保存原始序列与初始最小候选；每接受一次缩减都原子更新。再次用相同 `--output` 运行会自动从检查点继续未完成缩减，然后扫描新增用例；原始样本、样本 JSON、当前最小候选和每一步缩减理由都保留，新运行只对新增用例计费，摘要中以 `resumed=true` 标识。加 `--fresh` 可忽略旧检查点。

## 运行

```bash
python -m proto_robust.cli --goal goals/simple_message.json --output results/seed-20260930 --timeout 0.5
```

超时取 0.5 秒时，时序缺陷（解析器睡眠 1.5 秒）可被检出；宽松超时下它会表现为正常返回。固定种子和生成器顺序保证同一命令可重复。发现失败后保存：

- `<签名>#<索引>.original.session.json`：完整会话起点和原始交互顺序，可独立重放。
- `<签名>#<索引>.minimized.session.json`：当前最小候选的完整会话起点和交互顺序，可独立重放。
- `<签名>#<索引>.original.bin` / `.minimized.bin`：仅为兼容保留的字节拼接；交互边界以 session JSON 为准。
- `<签名>#<索引>.json`：签名（含缺陷位置与关键步骤条件）、复现证据、每步缩减理由、关键交互与字节位置。
- `campaign.checkpoint.json`：可恢复的活动状态。
- `campaign.json`：种子、预算、执行数量、预算耗尽/恢复标记和发现列表。

## 测试

```bash
python -m unittest discover -s tests -v
```

测试覆盖：两个同抛 `IndexError` 但位置不同的人工解析缺陷被分别分组；第二个缺陷的缩减保持原缺陷行与关键字节；多会话缺陷会删除良性中间交互但保留必需 arming 前置交互；一个交替失败的目标验证偶发失败保留全部重复试验证据；一次小预算运行在预算耗尽后经恢复继续发现时序超时，且原始样本、最小候选和每步缩减理由仍在。

系统不会访问外部目标；新增协议时新增目标模块、目标文件和生成器即可复用预算、隔离执行、签名分组、复现证据、缩减与样本保存流程。
